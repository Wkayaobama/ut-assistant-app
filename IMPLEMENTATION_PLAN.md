# UT-Assistant Implementation Plan

## Project Overview

Build a static Azure web app that serves as a front door to multiple Understand Tech assistants, with SSO authentication delegated entirely to the Understand Tech platform. Each assistant is tied to a specific tenant/team, enforcing RBAC through Understand Tech's SSO configuration.

---

## Architecture Summary

```
User → Azure Static Web App (Front Door)
  ↓
  Click Assistant Button
  ↓
Understand Tech Assistant URL (with api_key & model_id)
  ↓
Understand Tech SSO Login (Microsoft Entra ID)
  ↓
Assistant Chat Interface (authorized users only)
```

**Key Principle**: ALL authentication/authorization is handled by Understand Tech. Azure Static Web App is a simple, unauthenticated front door.

---

## Technology Stack

- **Frontend**: Pure HTML/CSS/JavaScript (no framework - keep it simple)
- **Hosting**: Azure Static Web Apps
- **Deployment**: GitHub Actions (auto-configured by Azure)
- **Authentication**: Delegated to Understand Tech SSO
- **Identity Provider**: Microsoft Entra ID (Demo_SSO tenant)

## Risk Assessment

### Low Risk:
- Static site deployment (Azure SWA is straightforward)
- GitHub Actions CI/CD (auto-configured by Azure)
- HTML/CSS/JS implementation (no complex framework)

### Medium Risk:
- Entra ID app registration (requires correct permissions)
- UT SSO configuration (first-time setup, must follow docs precisely)
- Redirect URI mismatch (common SSO troubleshooting issue)

### High Risk:
- API key exposure in client-side code
  - **Mitigation**: SSO enforced at UT level, api_key alone insufficient for access
- Subscription/tenant association
  - **Mitigation**: Test in current WISEKEY tenant first, transfer later if needed
