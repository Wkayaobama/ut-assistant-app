# UT-Assistant Front Door

**Simple, secure access to team-based AI assistants powered by Understand Tech.**

---

## Overview

This project provides a clean, static web application that serves as a front door to multiple Understand Tech AI assistants. Each assistant is protected by Single Sign-On (SSO) authentication via Microsoft Entra ID, ensuring only authorized team members can access their respective assistants.

### Key Features

- **Zero Backend**: Pure static HTML/CSS/JavaScript - no server required
- **Delegated Authentication**: All SSO handled by Understand Tech platform
- **Team-Based RBAC**: Access controlled via Microsoft Entra ID tenant membership
- **Simple Deployment**: Automated CI/CD via GitHub Actions → Azure Static Web Apps
- **Mobile Responsive**: Works on all devices

---

## Architecture

```
User Browser
    ↓
Azure Static Web App (Front Door)
    ↓
Understand Tech Assistant URL
    ↓
Understand Tech SSO Check
    ↓
Microsoft Entra ID (Demo_SSO Tenant)
    ↓
AI Assistant Chat Interface
```

**Security Model**:
- Static site has NO authentication (publicly accessible landing page)
- Authentication enforced at Understand Tech platform via SSO
- RBAC enforced via Entra ID tenant membership + UT team assignment
- API keys in URLs are insufficient for access without SSO authorization

## Quick Start

### Prerequisites

- Azure subscription with Static Web Apps capability
- GitHub account
- Azure CLI installed (`az --version`)
- Git installed
- Text editor or IDE

### Local Development

1. **Clone the repository**:
   ```bash
   git clone https://github.com/{ORG}/{REPO}.git
   cd UT-Assistant
   ```

2. **Serve locally** (Python):
   ```bash
   cd src
   python -m http.server 8000
   ```
   Open: `http://localhost:8000`

3. **OR serve locally** (Node.js):
   ```bash
   npx http-server src -p 8000
   ```

### Azure Deployment

See [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) for complete deployment instructions.

**Quick deployment**:
```bash
# Login to Azure
az login

# Create resource group
az group create --name rg-ut-assistant-fc --location francecentral

# Create Static Web App (requires GitHub repo)
az staticwebapp create \
  --name ut-assistant-app \
  --resource-group rg-ut-assistant-fc \
  --source https://github.com/{ORG}/{REPO} \
  --location francecentral \
  --branch main \
  --app-location "/src" \
  --login-with-github
```

## Configuration

### Adding a New Assistant

1. Edit `src/config.json`:
   ```json
   {
     "assistants": [
       {
         "id": "new-team",
         "name": "New Team Assistant",
         "description": "Description of assistant purpose",
         "api_key": "your_api_key_from_understand_tech",
         "model_id": "New Team",
         "team": "New Team",
         "tenant_id": "9398883c-8dd9-4fd9-b410-e42de5143116"
       }
     ]
   }
   ```

2. Configure SSO in Understand Tech (see [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) Phase 3)

3. Commit and push - GitHub Actions will auto-deploy

## SSO Configuration

### Understand Tech Setup (per team)

1. **Entra ID App Registration** (Demo_SSO tenant):
   - Create app registration
   - Note Client ID and create Client Secret
   - Configure redirect URI (from UT)
   - Add permissions: `openid`, `email`, `profile`

2. **Understand Tech Team SSO**:
   - Workspace → Teams → {Team Name} → Configure SSO
   - Fetch Redirect URI → add to Entra ID app
   - Enter Client ID, Client Secret, Tenant ID
   - Save and note Widget API Key

3. **Link SSO to Assistant**:
   - Assistant → Sharing → Enable SSO
   - Select configured team
   - Save

### Validation

Test SSO flow:
1. Open assistant URL from static site
2. Should redirect to Microsoft login
3. Authenticate with Demo_SSO tenant user
4. Should redirect to assistant chat interface

## Security Considerations

### API Key Exposure
- API keys are visible in client-side code (config.json)
- This is **acceptable** because:
  - SSO is enforced at Understand Tech platform
  - API key alone is insufficient for access
  - UT requires api_key in URL parameters (unavoidable client-side exposure)

### Access Control
- **Layer 1**: Static site is publicly accessible (no auth)
- **Layer 2**: Understand Tech SSO enforces authentication
- **Layer 3**: Microsoft Entra ID enforces tenant membership
- **Layer 4**: UT team assignment enforces RBAC

### Security Headers
See `staticwebapp.config.json` for configured headers:
- `X-Frame-Options: DENY`
- `X-Content-Type-Options: nosniff`
- `Content-Security-Policy`
- `Referrer-Policy`

## Troubleshooting

### Assistant link doesn't redirect to login
- Verify SSO is enabled in UT assistant settings
- Check Entra ID app registration has correct redirect URI
- Confirm Client ID/Secret are correct in UT team config

### Login succeeds but access denied
- Verify user is member of Demo_SSO tenant
- Confirm user is assigned to correct team in UT
- Check team SSO configuration is linked to assistant

### Deployment fails
- Check GitHub Actions workflow logs
- Verify Azure CLI authentication
- Confirm resource group exists in correct region
